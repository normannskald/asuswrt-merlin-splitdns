# Инструкция по работе с GitHub в Antigravity (`GITHUB_GUIDE.md`)

Это подробное пошаговое руководство для начинающих о том, как устроена публикация проекта на GitHub (`https://github.com/normannskald/asuswrt-merlin-splitdns`) и как продолжать разрабатывать аддон в **Antigravity**, чтобы все новые версии автоматически отправлялись на GitHub и были сразу доступны для установки и обновления с роутера.

---

## 1. Как устроена безопасная авторизация (без передачи пароля в чат)

В современной разработке **никогда не передают пароли от аккаунта** третьим лицам или ИИ-ассистентам. Вместо этого используется официальная утилита **GitHub CLI (`gh`)** и протокол **OAuth 2.0 Device Flow**:

1. На вашем компьютере уже установлены **Git** и **GitHub CLI (`gh`)**.
2. Авторизация выполняется командой:
   ```powershell
   gh auth login --web -h github.com -p https
   ```
3. Вы подтверждаете одноразовый код в своём браузере на официальном сайте `https://github.com/login/device`, после чего GitHub выдаёт защищённый токен, который хранится в системном хранилище учётных данных Windows (Windows Credential Manager).
4. Команда `gh auth setup-git` связывает Git с этим защищённым хранилищем, поэтому ни в исходном коде, ни в файлах проекта нет и не может быть никаких паролей или секретов.

## 2. Первичная отправка проекта на GitHub (уже настроено, справочно)

Когда вы создаёте новый репозиторий на сайте GitHub и выбираете в нём лицензию (например, **MIT License**), GitHub автоматически создаёт первый коммит с файлом `LICENSE`. Чтобы объединить локальный проект на вашем компьютере с историей репозитория на GitHub, используется следующая последовательность команд в PowerShell:

```powershell
# 1. Инициализация локального репозитория Git на ветке main
git init -b main

# 2. Привязка удалённого репозитория GitHub
git remote add origin https://github.com/normannskald/asuswrt-merlin-splitdns.git

# 3. Добавление всех файлов проекта и создание коммита
git add .
git commit -m "Initial release v1.0.0: Asuswrt-Merlin Split DNS GUI Addon"

# 4. Слияние с историей GitHub (если на GitHub уже был создан файл LICENSE)
git pull origin main --allow-unrelated-histories --no-edit

# 5. Отправка кода в основную ветку main на GitHub
git push -u origin main
```

## 3. Автоматическая отправка новых версий из Antigravity (`post-commit` хук)

В вашем локальном репозитории настроен специальный автоматический перехватчик Git — файл **`.git/hooks/post-commit`**:

```sh
#!/bin/sh
# Автоматическая отправка каждого нового коммита на GitHub
git push origin HEAD 2>/dev/null &
```

### Как это работает на практике?

- Каждый раз, когда вы просите **Antigravity** доработать аддон, исправить ошибку или добавить новую функцию и зафиксировать изменения (сделать `git commit`), Git **автоматически в фоновом режиме** выполняет `git push origin HEAD` и выгружает изменения на GitHub.
- Если вы хотите просто попросить ассистента в чате:
  > *«Добавь такой-то домен в пресет, подними версию до 1.0.1 и залей на GitHub»*
  — Antigravity сам внесёт правки, обновит номер версии, прогонит тесты и отправит коммит в репозиторий `normannskald/asuswrt-merlin-splitdns`.

## 4. Как выпускать новые версии, чтобы роутер видел обновление в веб-интерфейсе

В веб-интерфейсе аддона (`splitdns_page.asp`) и в скрипте управления (`splitdns.sh`) есть кнопка **«Проверить обновления»** (*Check for Updates*). Она сверяет версию, установленную на роутере, с переменной `VERSION="..."` в файле `splitdns.sh` в ветке `main` на GitHub.

Чтобы выпустить обновление, которое пользователи (и ваш собственный роутер) смогут установить одной кнопкой из веб-интерфейса:

1. Увеличьте номер версии (по правилам семантического версионирования `MAJOR.MINOR.PATCH`, например с `1.0.0` на `1.0.1` или `1.1.0`) в трёх файлах:
   - `splitdns.sh` — строка `VERSION="1.0.1"`
   - `install.sh` — строка `VERSION="1.0.1"`
   - `splitdns_page.asp` — строка `var CURRENT_VERSION = "1.0.1";` (и отображаемый бейдж версии)
2. Сделайте коммит изменений (или попросите об этом Antigravity):
   ```powershell
   git add install.sh splitdns.sh splitdns_page.asp README.md
   git commit -m "Release v1.0.1: описание изменений"
   git push origin main
   ```
3. Сразу после этого откройте веб-интерфейс роутера (`Split DNS` в разделе `WAN`), нажмите **«Проверить обновления»** — аддон обнаружит новую версию `v1.0.1` на GitHub и покажет зелёную кнопку **«Обновить аддон»**!

## 5. Полезные команды для проверки статуса в любой момент

Если вы хотите самостоятельно проверить состояние репозитория через терминал PowerShell в папке проекта:

| Команда | Что она делает |
| :--- | :--- |
| `git status` | Показывает, какие файлы были изменены и готовы ли они к отправке |
| `git log --oneline -n 5` | Показывает последние 5 коммитов в истории проекта |
| `git push origin main` | Вручную отправляет все зафиксированные коммиты на GitHub |
| `pwsh -File tests/run_all_tests.ps1` | Запускает полный набор автоматических тестов и проверку на отсутствие утечек секретов |
